## Arquitetura do Fluxo de Verificação de E-mail

### Fluxo via /register (preferencial)
```
/register (page.tsx)
  → step=register: form nome/email/senha
  → POST /api/auth/register
      → supabase.auth.signUp (anon key)
      → storeVerificationCode(email, code)  ← in-memory, TTL 5 min
      → sendVerificationEmail(email, code)  ← nodemailer (falha silenciosa em dev)
      → console.log([DEV] código: XXXX)    ← visible no terminal do servidor
  → step=verify: input 4 dígitos + cooldown 60s
  → POST /api/auth/verify-registration-code
      → verifyStoredCode(email, code)
  → step=success → router.push('/onboarding')
```

### Fluxo via /auth/verify-email (alternativo, recebe ?email=)
```
/login/register (legado) → POST /api/auth/send-verification-code → /auth/verify-email?email=X
  → POST /api/auth/verify-code → /onboarding
```

### lib/onboardingCodeStore.ts (store in-memory)
- `storeVerificationCode(email, code)` — salva com TTL de 5 minutos
- `verifyStoredCode(email, code)` — valida e remove após uso
- Funciona em dev/prod sem banco; perde dados se o processo reiniciar (aceitável para MVP)

## Deployment Workflow (Vercel)
1. **Build locally** – `npm ci && npm run build` (produces `.next` output).
2. **Deploy** – `npx vercel --prebuilt --prod` (uses the pre‑built `.next`).
3. **Alias management** –
   - Primary alias: `medsupapp.vercel.app` (auto‑assigned).
   - Custom domain alias: `www.medsupapp.com.br` (created with `npx vercel alias set <deployment> www.medsupapp.com.br`).
   - Apex redirect to `www` is defined in `vercel.json`.
4. **DNS** – CNAME `www` → `cname.vercel-dns.com`; optional A record `@` → `76.76.21.21` for root domain.
5. **Production branch** – Ensure the Vercel project is set to the branch you push to (usually `main`).

## Notas Críticas para o Agente de IA

### Regras de código (OBRIGATÓRIAS)
- **NÃO use** `react-hook-form`, `@hookform/resolvers`, `sonner`, `shadcn/ui` (`@/components/ui/*`) — não estão instalados
- **USE** React puro (`useState`, `useRef`, `useEffect`) + `fetch` nativo + `try/catch` explícito
- **Sempre** retorne `NextResponse.json(...)` nas rotas API — nunca deixe retornar HTML
- **Sempre** use `try/catch` em todo `fetch` no cliente
- Páginas que usam `useSearchParams()` precisam estar dentro de `<Suspense>` (Next.js 16 exige)
- TypeScript: use `err instanceof Error ? err.message : 'fallback'` — nunca `err: any`

### Arquitetura de autenticação
- Login principal: Google OAuth via NextAuth (`app/login/page.tsx`)
- Cadastro com senha: `app/register/page.tsx` (3 steps: register → verify → success)
- Verificação de e-mail: store in-memory em `lib/onboardingCodeStore.ts` (sem banco)
- Após verificação: redireciona para `/onboarding`

### SMTP / E-mail
- `lib/email.ts` usa nodemailer com variáveis `EMAIL_SERVER_*`
- Essas vars têm **placeholders** no `.env.local` — envio real não funciona ainda
- Em dev: o código aparece no console (`[DEV] Código de verificação para X: XXXX`)
- As APIs de e-mail **não quebram** se o SMTP falhar (catch silencioso)
